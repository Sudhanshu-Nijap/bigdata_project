🏛️ The 4 Big Data Engineering Pillars (Deep Dive)

Detailed breakdown of the architectural roles, parameters, and algorithms used in each component.

1. Apache Kafka
Ingestion Buffer
Distributed Message Broker & Traffic Shock Absorber

Technical Mechanism: Incoming tweets are serialized into UTF-8 JSON payloads and published to the partitioned Kafka topic twitter_tweets at localhost:9092.

Decoupled Asynchrony: In the web app, Kafka writes run inside background daemon threads (_kafka_worker). Even under massive streaming surges, the web UI never blocks or slows down.

The "Why": Protects the system against sudden traffic bursts (breaking news, viral hashtags), preventing socket congestion and downstream database crashes.

Source File: kafka_spark_streaming/kafka_producer.py
2. Apache Spark (PySpark)
Distributed Compute
Structured Streaming & Parallel ML Retraining

Technical Mechanism: Initializes a distributed SparkSession utilizing all available CPU cores (master("local[*]")). Ingests micro-batches via readStream every 2 to 5 seconds.

Distributed Tokenization & Vectorization: Parses JSON schemas, performs regex noise removal, and executes parallel ML scoring across worker threads.

The "Why": Single-threaded Python loops process records sequentially (O(N)). PySpark scales horizontally across partitions, making retraining on millions of archived records take seconds instead of hours.

Source File: kafka_spark_streaming/spark_consumer.py
3. Dual-Feature ML Model
Statistical AI
Word (1-3) + Char (3-5) N-Grams (97.7% Accuracy)

Technical Mechanism: Combines 45,000 Word N-Grams (captures semantic phrases & multi-word negations) with 25,000 Character N-Grams (captures subword morphology, typos, and slang) into an $L2$-regularized multinomial Logistic Regression classifier (C=2.5).

Entity Bias Calibration: In raw data, entity names (like Tesla) had false positive correlations. By calibrating on balanced factual syntax, biographical/factual sentences classify as Neutral (98.9% confidence).

Zero Hardcoding: 100% statistical ML inference with zero manual keyword dictionary overrides.

Source File: pyspark_model_training/sentiment_model.joblib
4. Dual-Tier Data Lakehouse
Hot / Cold Storage
MongoDB Atlas (Hot) + Snappy Parquet (Cold)

Hot Tier (MongoDB Atlas): Indexed on _id: -1 and is_verified. Serves live dashboard queries, keyword filtering, and Server-Sent Events with sub-20ms latency.

Cold Tier (Apache Parquet): The data_lakehouse.py engine migrates older tweets into columnar Snappy-compressed .parquet files.

Storage Optimization: Compresses dictionary metadata by >80%, keeps MongoDB fast, and enables PySpark to scan millions of rows in seconds using column pruning.

Source File: kafka_spark_streaming/data_lakehouse.py

🔄 Step-by-Step Data Journey (Lifecycle of a Tweet)

How a single raw tweet is scraped, sanitized, buffered, classified, persisted, and fed into the retraining loop.

1
Live Scraping, Topic Boundaries & Regex Sanitization
webapp/tweet_scraper.py

Captures live opinions for search terms (e.g., #AI, #Tesla, #Tech) using exact word-boundary regex (\b{term}\b) to eliminate topic bleed.

Transformations applied: Strips URLs (http[s]://\S+), cleans double handles (@@user → @user), purges synthetic dataset tokens (<unk>, <pad>), and trims extra whitespace.

2
Asynchronous Ingestion into Kafka Topic
kafka_spark_streaming/kafka_producer.py

Packages the sanitized tweet into a standardized JSON event dictionary containing id, text, topic, username, date, and timestamp.

Decoupling: Serializes JSON to UTF-8 bytes and pushes to Kafka topic twitter_tweets via non-blocking background threads, ensuring the web application never stalls.

3
Distributed PySpark Micro-Batch & Statistical NLP Inference
kafka_spark_streaming/spark_consumer.py

PySpark Structured Streaming ingests micro-batches every 2 to 5 seconds. The Dual-Feature Machine Learning pipeline extracts 70,000 composite N-Gram features and predicts sentiment class probabilities in <0.2ms.

Output Categories: Positive (praise/breakthroughs), Negative (complaints/bugs/hacks), Neutral (factual/encyclopedic), or Irrelevant (noise/off-topic).

4
Hot Operational Storage & Real-Time SSE Dashboard
webapp/app.py • static/js/dashboard.js

Enriched records are stored in MongoDB Atlas (Hot Tier) with indexed fields for sub-20ms queries.

Real-Time Telemetry: The server broadcasts new events over Server-Sent Events (/api/stream-tweets). The browser catches these event frames and updates the Chart.js doughnut charts and live teleprinter table without reloading the page.

5
Data Lakehouse Compaction into Snappy Parquet (Cold Tier)
kafka_spark_streaming/data_lakehouse.py

Historical records older than retention threshold are migrated from MongoDB into columnar Snappy-compressed .parquet files in data/lakehouse_cold_archive/.

Storage Optimization: Compresses repeating column metadata into dictionary encodings, saving >80% disk footprint and keeping MongoDB Atlas clean and fast.

6
Human-in-the-Loop Active Learning & PySpark Retraining Loop
kafka_spark_streaming/spark_retrainer.py

Operators can click on the dashboard to verify or correct mispredicted tweets, saving them as ground truth (is_verified: true).

Continuous Adaptation: PySpark batch retrains on the merged dataset (Cold Parquet + Verified MongoDB) across multiple CPU cores and dynamically hot-reloads the updated model with zero website downtime.
