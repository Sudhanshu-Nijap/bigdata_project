💡 Plain-English Architecture Guide

How This Big Data System Works End-to-End

An automated Big Data assembly line that collects live social streams, cleans noise, classifies sentiment with 97.7% statistical AI accuracy, displays real-time telemetry, and archives cold data into a compressed Data Lake.

🏛️ The 4 Core Big Data Technologies & Their Roles

What each tool does in this project and why traditional single-server scripts cannot handle it.

⚡ Buffer / Ingestion
1. Apache Kafka

What it does: Functions as a high-speed shock absorber and message highway. When 5,000 tweets arrive simultaneously during traffic spikes, Kafka queues them in memory and on disk.

Without Kafka: Heavy surges would freeze the web server or drop tweets completely.
🔥 Distributed Compute
2. Apache Spark (PySpark)

What it does: Distributes tweet cleaning, tokenization, and retraining across all available CPU cores simultaneously in micro-batches.

Without PySpark: Standard Python processes tweets one-by-one, taking hours for large datasets.
🧠 Pure AI / NLP
3. Dual-Feature ML Model

What it does: Uses 45,000 Word N-Grams and 25,000 Character N-Grams to classify text into 4 sentiments (Positive, Negative, Neutral, Irrelevant) with 97.7% accuracy.

Zero Hardcoding: No manual keyword lists or dictionary overrides; predictions are 100% statistical.
💾 Dual Storage
4. Data Lakehouse

What it does: Keeps recent live tweets in MongoDB Atlas (Hot Tier) for <20ms UI searches, and moves older tweets to Snappy-compressed Parquet files (Cold Tier).

Savings: Cuts storage disk footprint by >80% while enabling instant PySpark batch scans.

🔄 Step-by-Step Execution Flow

How a single tweet travels from the web to real-time charts and cold storage.

1
Live Scraping & Noise Stripping
webapp/tweet_scraper.py

The engine queries live public opinions on Twitter/X for active hashtags like #AI, #Tesla, or #Tech. It automatically strips broken URLs, system artifacts (<unk>, <pad>), and crypto spam.

2
Kafka Topic Queueing
kafka_producer.py

Tweets are converted into structured JSON payloads and published asynchronously to the twitter_tweets Kafka topic. This decouples web scraping from stream processing.

3
PySpark ML Sentiment Scoring
spark_consumer.py

PySpark Structured Streaming pulls micro-batches from Kafka. The AI model inspects word sequences and subword patterns to calculate confidence scores across Positive, Negative, Neutral, and Irrelevant in <0.2ms.

4
Hot Storage & Live Dashboard Telemetry
webapp/app.py

Classified tweets are saved to MongoDB Atlas (Hot Tier). The Flask server uses Server-Sent Events (SSE) to push live stream items into your browser, instantly updating Chart.js doughnut charts and KPI counters without page reloads.

5
Cold Parquet Lakehouse Archival
data_lakehouse.py

Older tweets are migrated out of MongoDB and saved into columnar Snappy-compressed .parquet files. This keeps MongoDB fast, eliminates database cost bloat, and provides high-density storage for analytics.

6
Active Learning & Automated Retraining Loop
spark_retrainer.py

If an operator corrects or verifies a sentiment label on the dashboard, it is stored as ground truth. PySpark loads these verified samples alongside the Parquet Lakehouse archive to retrain and hot-reload the AI model with zero downtime.
